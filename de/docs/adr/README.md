# ADR-Index

Langlebige strategische Betriebsentscheidungen für den Homelab-Kubernetes-Cluster. Wenn du eine passende ADR findest, **füge sie hier ein** und **verlinke aus dem Dokument, aus dem die Information kommt** – deklarierte ADRs ersetzen keine Code-Kommentare und keine README-Details.

ADRs dokumentieren **Entscheidungen**, nicht laufende Analysen oder Incident-Rekonstruktionen – dafür sind die Analysedokumente (`*_ANALYSE.md`, `*TROUBLESHOOTING.md`) und die [Known Issues](../issues/README.md) da.

## Nummernkreis

- `0000–0999` Architektur- und Betriebsentscheidungen (aktiv)
- Nummern werden **nicht wiederverwendet** – wenn eine ADR verfällt, wird sie nicht gelöscht, sondern per Status `Superseded by ADR-XXXX` markiert.
- Analysen/Incident-Rekonstruktionen gehören nicht in ADRs. Für sie ist `analysis/` (tempus, Confluence-artig) da – ADRs verlinken dorthin, wenn der Kontext hergeleitet wurde.

## Statuswerte

`Proposed` → `Accepted` / `Rejected` → (`Superseded by ADR-XXXX`) / (`Deprecated`)
